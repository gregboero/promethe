## Projet

- **Nom** : Prométhé
- **Description** : Agent IA autonome avec UI multiplateforme (Desktop, Web, Android, iOS)
- **Langage principal** : Kotlin (Kotlin Multiplatform)
- **Framework** : Ktor (backend gateway) + Compose Multiplatform (UI)

## Objectifs de l'agent

- Respecter les conventions de code existantes (ktlint, 0 violations)
- Écrire du code dans `commonMain` pour la UI (jamais de code platform-specific pour la UI)
- Utiliser `kotlin-logging` (`io.github.oshai.kotlinlogging`) pour le logging, jamais `println()`
- Compiler et tester avant de proposer des changements (`./gradlew.bat :composeApp:compileKotlinDesktop`)
- Garder la cohérence linguistique : UI en français, code/commentaires en anglais

## Contraintes

- Ne jamais modifier les fichiers de migration sans demander
- Toujours vérifier la compilation avant de proposer un commit
- Pas de dépendances externes sans accord explicite
- Les modules `api` et `shared` n'ont PAS de target `desktop` — utiliser les tasks appropriées
- Les fichiers de contexte (.promethe.md, SOUL.md, etc.) doivent toujours avoir des valeurs par défaut

## Structure du projet

```
promethe/
├── api/                    # Modèles API partagés (Kotlin Multiplatform)
├── composeApp/             # UI Compose Multiplatform
│   └── src/commonMain/     # ⚠️ Tout le code UI ici
├── gateway/                # Backend Ktor (routes, channels, scheduler)
│   └── src/jvmMain/
├── shared/                 # Core agent (AIAgent, outils, mémoire, GEPA)
│   ├── src/commonMain/     # Code multiplateforme
│   └── src/jvmMain/        # Implémentations JVM (browser, hooks, MCP)
├── profiles/               # Profils agent (USER.md, MEMORY.md)
│   └── developer/
├── docs/                   # Documentation (ARCHITECTURE.md, etc.)
└── scripts/                # Scripts CI/CD et utilitaires
```

## Stack technique

| Domaine | Technologie |
|---|---|
| Backend | Ktor 3.5.2 (CIO) |
| Frontend | Compose Multiplatform (Material 3) |
| Base de données | SQLite (via Exposed 1.5.0 + Flyway) |
| CI/CD | GitHub Actions (5 cibles) |
| Conteneurisation | Docker (multi-stage) |
| Logging | kotlin-logging + Logback |
| Sérialisation | kotlinx.serialization |
| HTTP client | Ktor Client |
| Filesystem | Okio (KMP compatible) |

## Conventions de code

- ktlint avec max-line-length=140
- Nommage des classes en PascalCase
- Fonctions en camelCase
- Constantes en SCREAMING_SNAKE_CASE
- Commentaires en anglais dans le code
- Labels UI en français
- Pas de `catch (_: Exception)` sans logging

## Workflow Git

- Branche principale : `main`
- Convention de commit : Conventional Commits (feat:, fix:, refactor:, docs:)
- Build vérifié avant chaque push
